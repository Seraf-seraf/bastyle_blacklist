# План AI-vector matcher

## Назначение

`ai_vector` matcher нужен для поиска медиа, похожего на уже забаненное
пользователем бота.

Модель не определяет, что хорошо или плохо. Она не должна банить картинку за
NSFW, насилие, политику, текст или любые другие смысловые категории. Единственный
источник запрета - действие администратора через `/ban`.

Правило работы:

```text
администратор банит медиа -> бот сохраняет векторные признаки
новое медиа приходит в чат -> бот ищет похожие признаки среди забаненных
score >= threshold -> медиа считается повтором или похожим вариантом ban
score < threshold -> медиа пропускается
```

## Вывод по GIF и анимированным стикерам

Подход подходит для GIF, Telegram animations и video stickers, потому что бот уже
умеет разбирать video-like медиа на кадры.

Но для таких медиа нельзя ограничиваться одним вектором на весь файл. Нужно
сохранять набор векторов по выбранным кадрам и считать совпадение по правилу:

```text
найдены похожие кадры >= min_matched_frames
и
доля похожих кадров >= min_matched_ratio
```

Это защищает от ложного срабатывания по одному случайно похожему кадру.

Для статичных картинок и статичных стикеров достаточно одного изображения и
одного набора векторов. Для GIF/animations/video stickers нужен набор кадров.

Отдельно нужно проверить текущую типизацию Telegram-стикеров:

- `MediaAnimation` уже обрабатывается как video-like;
- `MediaStickerStatic` сейчас может оказаться WebM video sticker после
  скачивания;
- `MediaStickerAnimated` нужно явно проверить на реальных данных Telegram:
  поддерживается ли скачанный формат текущим FFmpeg extractor или нужен
  отдельный путь.

## Документальные основания

Faiss:

- для cosine similarity векторы нормализуются, затем поиск выполняется через
  inner product;
- `IndexHNSWFlat` дает быстрый поиск ближайших векторов без обучения индекса;
- параметры HNSW: `M`, `efConstruction`, `efSearch`;
- HNSW индекс нужно считать производным файлом, потому что удаление отдельных
  записей неудобно. Источник истины должен быть в SQLite.

Ссылки:

- https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances
- https://github.com/facebookresearch/faiss/wiki/Faiss-indexes
- https://huggingface.co/nomic-ai/nomic-embed-vision-v1.5

## Архитектура

Рекомендуемый порядок matchers:

```text
exact
image_hash
video_like
ai_vector
```

Причина:

- `exact` самый дешевый;
- `image_hash` быстро ловит простые изменения статичных картинок;
- `video_like` уже ловит простые повторы GIF/video-like медиа;
- `ai_vector` дороже остальных, поэтому идет последним.

Общая схема:

```text
Go bot
  -> ContentMatcher
      -> ai_vector Go adapter
          -> локальный Python-процесс
              -> модель векторов
              -> SQLite
              -> Faiss HNSW индекс
```

Python-процесс должен быть долгоживущим. Не нужно запускать Python заново на
каждую картинку, иначе модель будет загружаться при каждом сообщении.

## Выбор модели

Стартовый кандидат: `nomic-ai/nomic-embed-vision-v1.5`.

Причины:

- локальная бесплатная модель;
- лицензия Apache-2.0;
- есть готовые форматы Transformers, Safetensors, ONNX;
- модель предназначена для векторного представления изображений.

Решение о финальном threshold нельзя брать из документации модели. Его нужно
подобрать на реальных данных проекта.

## Выбор индекса

Пользователь хочет сразу использовать быстрый индекс. Для первого внедрения
выбираем Faiss `IndexHNSWFlat`.

Требования к индексу:

- все векторы нормализованы;
- поиск похожести через inner product;
- результат поиска - ближайшие записи и score;
- решение о бане принимает Go matcher по тому же правилу `score >= threshold`;
- индекс хранится на диске как производный файл;
- при несовпадении версии модели, размерности вектора, количества активных
  записей, fingerprint активных векторов или checksum файла индекс
  пересобирается из SQLite;
- Faiss-файл читается только после проверки checksum, потому что загрузчик Faiss
  не валидирует целостность файла.

Начальные параметры:

```yaml
hnsw:
  m: 32
  ef_construction: 80
  ef_search: 64
```

Эти значения являются начальными. Их нужно проверить benchmark-тестами.

## Хранилище

SQLite остается источником истины. Faiss индекс нужен только для быстрого
поиска.

Нужны таблицы для статичных и покадровых векторов.

### Таблица запрета

Пример полей:

```text
id
file_unique_id
media_type
model_name
model_version
vector_dim
frames_count
active
created_at
```

### Таблица векторов кадров

Пример полей:

```text
id
ban_id
frame_index
position_millis
vector_blob
created_at
```

Для статичной картинки сохраняется одна запись с `frame_index = 0`.
Для GIF или video-like медиа сохраняется несколько записей.

### Таблица состояния индекса

Пример полей:

```text
model_name
model_version
vector_dim
index_type
index_path
active_vectors_count
active_vectors_hash
index_file_sha256
rebuilt_at
```

## Правила совпадения

### Статичные изображения

Алгоритм:

```text
получить вектор новой картинки
найти top_k ближайших векторов в HNSW
взять лучший score
score >= threshold -> blocked
```

### GIF, animations и video stickers

Алгоритм:

```text
извлечь кадры
получить вектор каждого кадра
для каждого кадра найти ближайшие забаненные кадры
сгруппировать совпадения по ban_id
выбрать ban_id с максимальным числом совпавших кадров
matched_frames >= min_matched_frames
и matched_frames / checked_frames >= min_matched_ratio -> blocked
```

Начальные параметры:

```yaml
threshold: 0.92
top_k: 5
min_matched_frames: 2
min_matched_ratio: 0.4
```

Значения нужно подобрать на реальных данных.

## Конфиг

Новая секция:

```yaml
matching:
  ai_vector:
    enabled: true
    db_path: "/var/lib/bastyle/bastyle.sqlite"
    index_path: "/var/lib/bastyle/faiss-image.index"
    model_name: "nomic-ai/nomic-embed-vision-v1.5"
    threshold: 0.92
    top_k: 5
    min_matched_frames: 2
    min_matched_ratio: 0.4
    hnsw:
      m: 32
      ef_construction: 80
      ef_search: 64
    service:
      url: "http://bastyle-ai-vector:8080"
media_config:
  max_frames: 10
  target_width: 320
  target_height: 320
  max_upload_bytes: 20MiB
  max_image_pixels: 16777216
```

Проверки конфига:

- `threshold` от `0` до `1`;
- `top_k > 0`;
- `min_matched_frames > 0`;
- `min_matched_ratio > 0` и `<= 1`;
- `max_frames > 0`;
- `target_width > 0`;
- `target_height > 0`;
- `db_path` не пустой;
- `index_path` не пустой;
- если `enabled = false`, сервис модели не запускается и не проверяется.

## Docker

Рекомендуемый вариант для Docker Compose - два сервиса:

```text
bastyle-blacklist
bastyle-ai-vector
```

Причины:

- Go-бот остается легким и простым;
- Python-зависимости не смешиваются с основным бинарником;
- модель загружается один раз в отдельном процессе;
- проще измерять память и перезапускать AI-часть отдельно.

Требования к `bastyle-ai-vector`:

- Python runtime;
- `faiss-cpu`;
- библиотека для запуска модели;
- `pillow`;
- `numpy`;
- общий volume `/var/lib/bastyle`;
- кэш модели в volume или внутри образа.

Текущий лимит `512m` для AI-сервиса, скорее всего, мал. Для первого запуска
нужно поставить отдельный лимит, например `2g`, затем измерить фактическое
потребление памяти.

## Критерий готовности

Функционал считается готовым, когда выполняются условия:

- картинка, забаненная через `/ban`, удаляется при повторной отправке;
- измененная версия этой картинки тоже удаляется;
- визуально похожая, но разрешенная картинка не удаляется на тестовом наборе;
- GIF или video-like медиа блокируется только при совпадении нескольких кадров;
- NSFW или любой другой смысловой контент не блокируется сам по себе, если его
  не банили;
- после перезапуска контейнеров blacklist и индекс восстанавливаются;
- при удалении или устаревании индекса он пересобирается из SQLite.
